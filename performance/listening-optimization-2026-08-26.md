# 听力页性能优化记录

日期：2026-08-26

## 结论

听力页原先把所有折叠分组中的章节、题目和材料链接都提前放进 DOM。页面虽然只显示 7 个折叠卡片，浏览器仍需创建约 861 个节点。

现在仅渲染首层分组摘要；用户第一次展开分组时再挂载其下一层内容，继续展开章节或问题时才挂载材料链接。

## 同环境复测

| 指标                |    优化前 |    优化后 |                         变化 |
| ------------------- | --------: | --------: | ---------------------------: |
| 硬加载 DOM 节点     |       865 |       201 |                       -76.8% |
| 长列表测试 DOM 节点 |       861 |       197 |                       -77.1% |
| 初始传输            | 205.9 KiB | 198.8 KiB |                        -3.4% |
| 硬加载完成          |  446.2 ms |  428.6 ms |                        -3.9% |
| 客户端切换中位数    |  181.5 ms |  181.4 ms |                     基本不变 |
| 客户端切换 P95      |  223.2 ms |  256.2 ms | 3 次采样波动，不作为回归结论 |

## 181 ms 的判断

优化后服务端首字节中位数为 17.4 ms，听力页客户端切换中位数为 181.4 ms；同期其他学习页为 169.6–196.5 ms。剩余切换时间主要属于通用的 Next.js 客户端路由、脚本执行和测试中额外等待两个稳定帧的成本，而不是听力页隐藏 DOM 的特有成本。

因此，本轮不以增加缓存复杂度或改变数据一致性为代价追逐小幅、容易受采样噪声影响的路由数字。后续若要继续降低切换耗时，应把基准拆成 RSC 请求、React 提交和稳定帧三段，并增加采样次数后再针对最大的一段处理。

## 交互验证

- 初始：197 个 DOM 节点，7 个听力内容分组，0 个材料链接。
- 展开教材：210 个节点，只挂载 2 个章节摘要。
- 再展开第一个章节：252 个节点，挂载 11 个材料链接。
- 全部 127 项自动化测试通过。
