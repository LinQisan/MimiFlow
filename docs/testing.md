# 测试

默认验证入口是 `npm test`。它运行一个真实浏览器场景，覆盖未登录访问、账户 A 的到期复习与评分、退出后的权限，以及账户 B 的数据隔离。评分后还会读取测试数据库，确认复习记录和事件只写入账户 A。

## 运行

需要本机 PostgreSQL、可用的 `DATABASE_URL`、Node.js 22–26 和 Chrome/Chromium。若浏览器不在常见安装路径，设置 `E2E_BROWSER_PATH` 为可执行文件的绝对路径。

```sh
npm test
```

脚本先创建独立测试数据库并执行 `npm run db:push`，随后执行生产构建、启动 Next.js 和浏览器。原开发数据库只用于取得本地连接配置，不会被写入。测试结束后删除临时数据库；失败时同样尝试清理。不要在开发过程中反复运行完整 E2E，完成改动后再运行。

每次运行都会在 `outputs/e2e/<运行编号>/` 留下 `result.json` 和截图。结果文件包含已通过的步骤、运行时间和提交 SHA；目录由 Git 忽略。失败时保留 `failure.png` 供检查。

目前 E2E 场景位于 `scripts/e2e/review-flow.mjs`。新增场景应通过页面和真实服务验证完整用户流程，并在结束时保存可复验的结果与截图。

CI 将生产依赖审计与类型检查、lint、E2E 分成独立的必过任务，安全告警不会让功能检查被跳过。Prisma 7.10.0 固定了有漏洞的间接依赖 `mysql2`；根目录的 `overrides` 将该版本修复到 3.23.1。升级 Prisma 后应重新检查依赖树并移除不再需要的覆盖。
